# Conversational coach P0 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Complete each task's failing test, implementation, verification and scoped review before integration. Checkboxes record actual results.

**Goal:** Extend the existing native Mivu into a durable, live conversational food tracker with correct historical and selective corrections.

**Architecture:** Preserve Foundation values and the DiaryStore actor. Migrate its private persistence to SQLite, extend the existing authenticated streamed client, and join those boundaries with persisted turns, validated local operations and the existing native meal screens.

**Tech Stack:** Swift 6, SwiftUI/UIKit/PhotosUI, system SQLite3, Foundation URLSession, existing CryptoKit/Keychain/OAuth, Swift Testing/XCTest and XcodeBuildMCP. No new third-party dependency or backend.

**Spec:** [Conversational coach design](../specs/2026-10-12-conversational-coach-design.md). Read the [feature audit](../../verification/2026-10-12-coach-feature-audit.md) and current source before implementing.

## Global constraints

- One existing Mivu app, iPhone/iOS 26+, English-only UI, native warm/glass design.
- Preserve all legacy profiles, photos, source metadata, day IDs, revisions, lineage, tombstones and archives.
- No diabetes/celiac functionality, invented history, duplicate records, negative compensation entries or successful-save message before persistence.
- No credentials in records/archives/logs, paid fallback, publication, new service or legal acceptance. Real owner authorization is a distinct gate.
- Keep nullable nutrients and missing/untracked days distinct from explicit known zero. Calculations derive from committed records.
- Preserve current public actor APIs unless a documented addition is needed; shared model/store/archive edits are serialized.
- Sol owns feature implementation/review; Luna handles mechanical documentation. Parallelize Tasks 1 and 2 only. One native simulator/test owner at a time.

## Review focus

1. Interrupted migration or a missing/replaced/corrupt database must not acknowledge a write or resurrect stale JSON data.
2. Retrying a model turn with fresh call IDs must not duplicate a food record; a failed commit must preserve input and suppress save claims.
3. A profile/account switch or direct item edit during inference must fence the late result.
4. “Yesterday” after midnight and unspecified meal time must preserve the correct day and honest time precision.
5. A model's fabricated verified source, unknown item ID or selective correction touching another item must be rejected or require clarification.

## Task 3 — Persisted conversation and guarded food operations

**Files:** Create `ios/Mivu/Coach/CoachModels.swift`, `CoachEngine.swift`, `CoachTools.swift`, `FoodEvidence.swift`, plus focused coach tests. Extend `DiaryModels.swift`, `DiaryStore.swift`, `DiaryDatabase.swift` and `DiaryArchive.swift` together under one owner.

**Interfaces:** `CoachTurn: Codable, Equatable, Sendable, Identifiable` owns `id: UUID`, `capturedAt: Date`, `text: String`, `photos: [MealPhoto]`, `state: CoachTurnState`, `assistantText: String?`, and `[CoachReceipt]`. States are `captured`, `analyzing`, `waitingForConnection`, `needsRetry`, `needsClarification`, `completed`. `CoachReceipt` records `operationKey: String`, `turnID: UUID`, `dayID: UUID`, optional meal/item IDs, committed revision and a result JSON string. `CoachContext` is a bounded projection of the selected profile, clock/day, actual meal/item IDs and sources, weights and recent turns; it contains no credentials or historical photo bytes.

Add `DiaryStore.captureCoachTurn(text:photos:at:turnID:expectedProfileID:) throws -> CoachTurn`, `coachContext(turnID:expectedProfileID:) throws -> CoachContext`, `applyCoachFood(turnID:targetLocalDate:items:expectedProfileID:) throws -> CoachReceipt`, `applyCoachItemCorrection(turnID:mealID:item:expectedRevision:expectedProfileID:) throws -> CoachReceipt`, `closeCoachDay(turnID:localDate:completeness:expectedProfileID:) throws -> CoachReceipt`, and `completeCoachTurn(turnID:assistantText:expectedProfileID:) throws`. Text is String, photos `[MealPhoto]`, dates Date or local ISO String as named, items `[FoodItem]`, item `FoodItem`, revisions Int and IDs UUID. Bind profile IDs locally. Operation keys combine the persisted turn, operation kind and target; food logging has one created meal per turn/date, independent of regenerated call IDs.

`CoachEngine.run(turnID:expectedProfileID:) async throws -> CoachTurn` consumes these methods and an injected authenticated response closure. It caps a turn at eight inference rounds and sixteen tool calls, validates all arguments, and only executes the small declared namespace. Fixtures use that same boundary. Extend the snapshot with v1-safe empty coach turns and day `closedAt`; archive v2 includes them. Existing meal input/output and zero-intake/completeness semantics remain reusable and guarded. Photos linked into a meal stay referenced by the turn; explicit photo deletion must not leave a retained duplicate in conversation storage.

- [ ] Add failing tests for the owner's two-eggs/three-bread/salad input, “half the bread” changing only bread, yesterday's 30g chocolate, resumed references after relaunch, untracked-day closure, invalid/foreign IDs, stale direct edits, duplicate/reordered calls, and a failed commit that changes neither records nor receipts. Compare totals to saved item values, not provider prose.
- [ ] Define additive journal/time-precision/close-day fields with v1-safe decoding and a v2 portable archive. Test legacy imports plus new pending turns, photos, receipts and deletion roundtrip before changing the schema.
- [ ] Persist raw turns before inference; expose only implemented namespaced functions for context/meal retrieval, nutrition lookup, food logging/item correction and day closure. Bind owner/account in code. Stable operation keys are based on persisted turn and target, independent of regenerated provider call IDs. Reuse stored receipts on retry.
- [ ] Use actual retrieved nutrition evidence when available; otherwise mark estimates/label transcriptions uncertain. Never accept a model's unsupported “verified” label. Preserve serving basis and unchanged item nutrient sources. Lookup failure retains capture and honest uncertainty.
- [ ] Commit food changes and their receipts atomically through DiaryStore. Never hold a database transaction while awaiting network work. Return actual results to the model; on failed/partial work, render explicit committed/failure facts instead of an unverified save statement.
- [ ] Resolve historical dates using the persisted turn clock and profile timezone. Reuse waking-day choice; require clarification when ambiguous. Closing untracked preserves records and excludes the day from complete-intake averages.
- [ ] Pass focused coach, legacy archive, ownership and retry tests; review the connected storage/transport flow independently and commit exact files.
