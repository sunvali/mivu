# Workouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Simple, complete workout logging on iPhone (gym live sessions, cardio, Pip, machine photo, import/export) on the existing diary storage.

**Architecture:** Extend the existing `WorkoutSession` JSON payload and its `workout` table; add one `routine` collection; archive v5. Pure logic (catalog, burn, bests, plates, CSV) lives in small value-type files under `ios/Mivu/Workout/` with Swift Testing suites. UI is SwiftUI in the same folder, reusing Mivu tokens and the existing store/view-model write path (`model.change { … }`).

**Tech Stack:** Swift 6, SwiftUI (iOS 26), SQLite via `DiaryDatabase`, ActivityKit, UserNotifications, Swift Testing, XcodeBuildMCP.

**Spec:** `docs/superpowers/specs/2026-11-04-workouts-design.md`

## Global Constraints

- iPhone only; Android untouched. One PR for everything; one archive bump to version 5.
- No jargon on screen: never show "RPE", "volume", "1RM", "PR", "W/D/F". Use "How hard?", "New best", "Warm-up", "Drop set", "To failure".
- Colors only from `ios/Shared/MivuColors.swift`; workout accent `diaryWorkout`, burn tint `diaryTintBurn`. SF Symbols, not emoji.
- Dynamic Type, VoiceOver labels, reduced motion, 44-point minimum targets on every new control.
- Every live-workout change is written in its own transaction before the UI shows it done.
- Burn never changes the food budget unless `exerciseCreditPercent` is 50 or 100.
- Pip never suggests workouts, weights or plans; never invents a burn number.
- Machine photos go to ChatGPT only after the existing OpenAI sharing consent; photos are not stored.
- Synthetic inputs only in tests; no real exports, photos or tokens.
- Write the smallest failing test first. Run native tests with XcodeBuildMCP (`test_sim`, scheme `Mivu`, `-only-testing:` the suite) and record the source SHA.
- Commits: Conventional Commits, owner's identity, no assistant/AI mention, no `Co-Authored-By`.
- Every new file lives in a synchronized group (`ios/Mivu/…`, `ios/MivuTests/…`); no `project.pbxproj` edits needed.

## Review Focus

1. **App killed mid-set, then relaunched days later**: the active workout, its ticked sets and the banner return; it never counts in totals until finished. Test in Task 7.
2. **No body weight recorded**: burn is `nil`, the UI shows "Add weight for kcal", and adjusted "left" is unchanged. Test in Task 5.
3. **lb user**: wheels step 5 lb, stored `loadKg` round-trips to the same displayed lb value after save and reload (no 132.3 → 132.2 drift). Test in Task 9.
4. **Re-importing the same Strong/Hevy file, or a file with decimal commas**: no duplicates; weights parse correctly. Test in Task 16.
5. **Coach edit of a workout created by the new UI**: fields Pip did not mention (`exerciseID`, set `type`, `groupID`, `effort`, `distanceMeters`) survive. Test in Task 14.
