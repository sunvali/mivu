# Motion Companion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Pip as the only shipping Rive companion, a small bundled-character selection foundation and responsive native motion, with a separately reviewed roadmap for a broader Mivu experience redesign.

**Architecture:** Keep durable diary operations and inference unchanged. A root-owned transient presentation reducer consumes explicit successful-operation receipts and visibility/power policy; one shared Rive worker renders at most one active character from a local catalog. A root-owned local preference selects a stable character ID; Pip is the only bundled entry today. SwiftUI continues to own navigation, controls, layout and accessible status text.

**Tech Stack:** Swift 6, SwiftUI, iOS 26+, Swift Testing, XCTest UI tests, official Rive Apple `RiveRuntime` 6.28.1 through Swift Package Manager, XcodeBuildMCP for native verification.

**Spec:** [`../specs/2026-10-17-motion-companion-design.md`](../specs/2026-10-17-motion-companion-design.md), approved in conversation for planning on 2026-10-17. Its earlier “owner review” status is historical; the owner subsequently selected original Pip (`02-pip-identity.png`) and cancelled further character alternatives. This plan does not authorize implementation.

## Global Constraints

- “Animation must never delay a save, obscure an error, or interfere with editing.”
- “Use SwiftUI for navigation, controls, sheets, numeric changes, and layout transitions. Use one bundled, original Rive character for expressive reactions.”
- “No database migration, remote asset downloads, paid services, or new analytics.”
- “No new gamification, streak penalties, reward currency, notification campaigns, voice/lip-sync, sound effects, background animation, or changes to food analysis.”
- “There is at most one playing companion, on the selected, visible root screen.”
- “Keep only the newest pending success; never queue a chain of celebrations.”
- “A success hidden by an editor/detail can be consumed once on return within 10 seconds of commit, otherwise discard it.”
- “Reduce Motion: static poses only; no blink, squash, travel, loops, animated number interpolation, or custom scroll animation.”
- “Low Power Mode or serious/critical thermal state: use static poses, avoiding idle/processing loops and decorative one-shots until the condition clears.”
- “An illustration or motion storyboard is not a functioning Rive asset. Asset authoring/export is a required deliverable.”
- “Target a character file below 512 KiB; hard limit 1 MiB.”
- Preserve English-only MVP, stored language/profile/archive data, durable capture, backup wording, recovery, deletion guards, Coach row identities, pagination and intentional scroll-follow behavior. Retain existing capture haptics exactly once.
- New user direction permits a whole UX/UI redesign and retains Rive. It does not define every replacement flow: Task 1 produces the broader design milestone before any newly redesigned flow is coded. Existing Precision Glass behavior is the implementation baseline until a replacement is explicitly reviewed.
- Original Pip is selected: use `design-system/mivu/characters/pip/reference.png`, `context.png` and authoritative `MOTION.md`. Preserve its orange fox body, cream muzzle/chest/tail tip, dark brown paws, large pointed ears, teal scarf and original silhouette. ## Review Focus

1. A successful write followed by profile switching or failed refresh must not celebrate in the wrong diary; Task 5 checks receipts and selected profile after suspension.
2. Hidden or resource-constrained surfaces must never resume an interrupted celebration or keep a timer/player ticking; Tasks 3, 4 and 6 exercise cancellation and current-state restoration.
3. Persisted receipts, repeated same-kind fresh operations and wall-clock boundary values must not cause replay or dropped legitimate feedback; Task 3 uses explicit time and event identities.
4. Missing/corrupt artwork or wrong binding types must leave capture, navigation and error text usable; Tasks 4 and 7 exercise the real fallback path.
5. A 100-turn Coach thread, largest text and keyboard focus must retain its reading anchor/composer while decorative state changes; Tasks 6 and 7 preserve and exercise existing history contracts.

## Task 3: Implement Pure Motion Policy and Event Arbitration

**Files:** Create `MivuMotion.swift`, `MotionPolicy.swift`, `CompanionPresentation.swift`, `MotionPolicyTests.swift`, `CompanionPresentationTests.swift` in the mapped directories.

**Interfaces:** Define these exact small types in `CompanionPresentation.swift`:

- `CompanionPose: Int, CaseIterable`: `resting = 0`, `attentive = 1`, `thinking = 2`, `saved = 3`, `reviewed = 4`, `recovery = 5`, `greeting = 6`.
- `CompanionSurface`: `.today`, `.coach`; absence means no eligible root.

**Files:** Create editable `design-system/mivu/characters/pip/source/`, `AUTHORING.md`, `asset-manifest.json`, Pip sheet, production `.riv`, preview `PipPreview` and seven fallback image sets (`PipResting`, `PipAttentive`, `PipThinking`, `PipSaved`, `PipReviewed`, `PipRecovery`, `PipGreeting`), `CompanionView.swift`, `CompanionAssetTests.swift`; modify Xcode project and lockfile.

**Interfaces:** Consumes selected Pip's `MOTION.md`, Task 2's descriptors/selection and Task 3's pose/output types. `CompanionView(presentation: CompanionOutput, darkMode: Bool, size: CGFloat, runtime: CompanionRuntime)` is decorative. `@MainActor @Observable final class CompanionRuntime` exposes `init(bundle: Bundle = .main)`, `select(_ character: CharacterDescriptor) async`, `attach(eligible: Bool) async`, `apply(_ output: CompanionOutput, darkMode: Bool) async`, `stop()`, `private(set) var isReady: Bool`, `private(set) var loadFailed: Bool`; retain one shared `Worker` and only the current descriptor's `File`, artboard, state machine and view-model instance internally; release the old file/player on selection, without a per-character cache. Keep native frame updates inside runtime/view, never view-model state. `select` changes descriptor identity and is a no-op for an already selected ID; loading/retry belongs to `attach`. Attachment eligibility starts false. Root derives eligibility as `MotionPolicy.Playback.animated` for the selected, visible, uncovered active root and forwards actual edges to `attach(eligible:)`: false stops playback and invalidates/cancels any pending attachment load; each false→true edge receives one new attachment generation and permits at most one load attempt. Repeated true updates, failed loads and `apply` calls do not retry. An already ready descriptor reuses its loaded file on attachment without replaying an obsolete action. A failed descriptor retries once only on its next false→true attachment; never in a timer, on render updates or on same-ID selection.

Canonical authoring contract is identity-independent: artboard `MivuCompanion`, state machine `Companion`, bound view model `CompanionModel` with an authored default instance. Its top-level property paths are Number `pose` restricted to integers 0...6 (default 0), Boolean `darkMode` (default false), and Trigger `react` (no queued trigger on creation/attachment). Author these data-binding properties for the concurrency API and bind them to the state-machine transitions; legacy-only state-machine inputs do not satisfy this contract. Host sets `pose` and `darkMode` on the retained bound instance before firing `react`. Fresh saved/reviewed/greeting actions fire `react`; a genuinely new same-kind event fires it again. Resting `react` fires only for a new eligible 12-second blink deadline. Setting attentive/thinking/recovery pose is sufficient and must not fire `react`; an ordinary resting update must not trigger a blink. Changing pose interrupts the current reaction. One-shot branches finish at REST and stop advancing; host restores the current non-rest underlying pose at the duration deadline, independently of a completion callback. Appearance-only changes update `darkMode` without re-firing `react`, resetting pose or restarting the action. Declare these exact names/defaults in the manifest and assert them at load. No audio/text/external assets or scripts are needed.
