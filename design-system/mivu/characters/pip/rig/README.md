# Pip layered rig

`pip.svg` is the editable source of truth for Pip's vector rig. `build.py`
converts it to `ios/Mivu/Resources/Characters/pip/pip-rig.json`, which the app
bundles. Never hand-edit the JSON.

## Commands

```sh
python3 -m venv .venv && .venv/bin/pip install cairosvg pillow   # once, at repo root
.venv/bin/python design-system/mivu/characters/pip/rig/build.py              # write pip-rig.json
.venv/bin/python design-system/mivu/characters/pip/rig/build.py --png OUT    # also render each set + fallbacks
.venv/bin/python design-system/mivu/characters/pip/rig/test_rig.py           # asset checks
```

`build.py` itself needs only the standard library; `--png` needs `cairosvg`. `--png` also
rewrites the fallback images named in each imageset's `Contents.json`: `PipResting` and
`PipPreview` (standing, light + dark) and `PipCoach` (seated, light only).

## SVG conventions

- Artboard 512 × 512, ground line y 472.
- Every `<g id="…">` is one part and holds exactly one direct `<path>`; its
  `fill` is the light fill, optional `data-fill-dark` the dark-appearance fill.
- `data-pivot="x y"` is the rotation/scale pivot, in the group's own coordinates.
- Group `transform`s (matrix/translate/scale/rotate) are flattened into the
  JSON paths and pivots. Paths use absolute `M L C Q Z` commands only.
- Parent = nearest ancestor group with an id. `data-parent` overrides it, so a
  part can be drawn behind its parent (ears, neck and rims sit before `head` in
  the file but move with it). `head`'s parent is `body`, drawn later.
- Draw order: `z` is document order. A child drawn after its parent's own path
  is in front of it; use `data-parent` for parts that must sit behind.
- `data-set="standing|seated|curled"` marks pose-set parts (inherited by
  children); no attribute means shared.
- Face alternatives: `data-shape="slot.name"` (`mouth.closedSmile`,
  `eye-l.half`…). `display="none"` means `visible: false` in the JSON for that
  part and everything nested inside it; exactly one shape per slot is shown by
  default. Sub-parts of a shape (iris, glint,
  tongue) are its children and need no `data-shape`. Hidden-by-default extras
  (cheek blush) also use `display="none"`.
- `-l`/`-r` mean the viewer's left/right in every view.

## Head views

Pip's head exists in three views so he can turn. Each view provides the same
named parts and face shapes, so the runtime swaps a whole view at once.

| View | Source | Notes |
|---|---|---|
| `right` (default) | dark seated Pip, `../reference.png` | 3/4, snout to the viewer's right, `ear-l` swept out, `ear-r` upright |
| `front` | `../storyboard.png` row 3 col 4 | near-frontal, slight turn right |
| `left` | generated by `build.py` | mirror of `right` |

- A view is a group `<g data-view="right|front|left">`; parts inherit the view
  and the JSON carries `"view"` (null = shared, e.g. the body). Part ids are
  `name@view` (`head@front`, `eye-l.open@left`); `shape` stays the slot name
  (`eye-l.open`). Only `right` is visible by default.
- `<g data-view="left" data-mirror-of="right" display="none"/>` asks `build.py`
  to reflect the `right` view about `head@right`'s pivot x. Mirroring swaps
  `-l`/`-r` in ids and shapes, so `-l` stays the viewer's left. Eye glints are
  not reflected (they follow their iris), so the light stays on the same side.
  The scarf knot is body art and is mirrored or kept by the body's own views.
- The heads were traced from the paintings (palette quantisation, per-region
  contours, cleaned into the named parts) and checked by overlay; the scarf
  hides the chin; the jaw ends in a gently rounded chin that the scarf sits under. Other
  mouth and eye shapes are derived from each traced face; `mouth.smallOpen` is
  the waving Pip's open smile, mirrored.

## Parallax for small turns

Face features carry `data-parallax="f"` (JSON `"parallax"`, default 0). For a
small turn `t` in -1…1 inside a view, the runtime slides each part sideways by
`f × t × parallaxScale` artboard units (`parallaxScale` is in the JSON, 20).
Factors are relative to the parent, so a part's total slide is the sum along
its parent chain: head outline and ears 0, eyes 0.45, brows 0.35, blush 0.45,
muzzle 0.6, mouth 0.6 + 0.3, nose 0.6 + 0.4 = 1.0 (the snout leads the turn).
Past about ±0.3, swap to the next view instead.

## Body sets

The body exists as three sets, each traced from its painting like the head:

| Set | Source | Ids |
|---|---|---|
| `standing` (Today) | `../storyboard.png` row 1 col 1 | `body`, `tail-1`… |
| `seated` (Coach) | dark seated Pip, `../reference.png` (the head's painting) | `body@seated`… |
| `curled` | curled Pip, `../reference.png`, mirrored to face right | `body@curled`… |

- Every set has `body, chest, chest-fluff, arm-l/r → forearm → paw, leg-l/r → foot,
  tail-1 → tail-2 → tail-3 → tail-4, scarf-knot → scarf-end-l/r, shadow`. Pivots sit at the
  joints (shoulder, elbow, wrist, hip, ankle, each tail segment's base); `body` pivots on the
  ground. `heart-1…3` are shared and hidden.
- Fur is painted under the arms, the neck under the head, the tail base and behind the scarf,
  so joints can rotate without gaps. Parts the painting doesn't show (far hind legs, curled
  arms and scarf ends) sit fully behind the visible ones.
- The body faces right; facing left is a runtime mirror of the whole character.
- Each set's `body` carries `data-mount="k tx ty"` (JSON `"mount"`): the shared parts
  parented to `body` (the head views, hearts) are drawn at `head point × k + t` on the
  active set's body. All three sets use k = 0.97 so the ear tips clear y 32.
- The teal scarf is body art, drawn by hand over the painting as smooth curves (band and knot,
  hanging end, front flap); it sits under the rounded chin (in `curled` the paws do).
- `frames.today` is the standing set's bounds plus 8; `frames.coach` the seated set's bounds
  plus 6, widened to 76:66.
- The body was generated by a one-off tracer: fur outlines come from the painting's silhouette
  (smoothed), split into parts by hand-placed zones. Each painted shade (tail cream, chest cream,
  tail shadow, brown socks) is one smooth shape drawn over the painting and shared by every part
  it crosses (child parts such as `tail-3.cream`), so joins never change colour. Checked by overlay.
